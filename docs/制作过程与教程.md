# 制作过程与使用教程

> 上半部分（一到八节）是项目复盘，下半部分（九、十节）是教程和未来计划

## 零、开发方式：vibe coding

这个项目是 **vibe coding** 做出来的：我用自然语言描述想要什么（界面上要有「洛谷计分器」几个字、要有开始按钮、按下去要能输出账号密码和 `_client_id` 去查已通过的题），AI 负责改 `luogu_scorer.cpp`、编译、截图给我看，我看效果再提意见，如此往复。

人的工作主要是三件事：**提需求、看效果、拍板**（比如「字有些粗有些细，统一成粗的」「难度颜色差了点感觉，回档」「不到 50 题不要用平均数，用总分除以 50」）。AI 的工作是写代码、排工具链故障、跑数据、写文档。所以这份文档里的「踩坑」基本都不是提前设计好的，而是被截图和报错一步步逼出来的。

这样做的代价是过程比较跳：功能是长出来的，不是规划出来的。好处是每一版都能立刻看到、立刻否掉，最后留下来的东西确实是我想要的样子。

## 一、为什么做这个

洛谷的个人主页能看通过记录，但要算「我的水平大概多少分」「哪些题值得做」，得自己一题一题对难度。想要的是一个本地小工具：输入账号，直接给一个评分，按难度分组列出已通过的题，再顺手推荐一道明天的练习题。

## 二、需求拆解

第一版的目标很朴素：

- 启动页：大字「洛谷计分器」+ 一个「开始」按钮；
- 点开始后：出现账号、密码、`_client_id` 输入框；
- 登录成功后：把已通过的题目列出来（题号 + 题目名 + 链接）。

后来在使用中一点点加：

- 三种登录方式（密码 / Cookie / 公开查询）——因为密码登录经常被人机验证拦；
- Rating 计分（B50）——光有题目列表没有「水平」；
- 按难度分组 / 按分数 / 按题号三种视图；
- 每日一题、推分推荐——列表看久了还是不知道下一题做什么；
- 个人账号 + 本地成绩归档——想留历史记录。

## 三、技术选型

- **Win32 + C++，单文件**：不要 Electron、不要 Python 环境，双击就能跑，发给别人不用装东西。
- **静态链接**（`-static -mwindows -municode`）：不依赖 MinGW 运行库，产物 1.0 MB 左右。
- **WinINet** 发请求：系统自带，不用引入 libcurl。
- **自己写 JSON 解析**：只需要取字段，不值得为它拉一个库。
- **数据全部落 `data\` 目录**：配置、分数表、本地账号、成绩快照都是纯文本，出问题能直接打开看。

## 四、界面与交互

- 深色卡片式布局，登录区一张卡片，下面是运行日志。
- **DPI 感知**：一开始在 150% 缩放的屏幕上截图，字全是糊的、布局还被截断。后来在 `wWinMain` 里调 `SetProcessDpiAwarenessContext(PER_MONITOR_AWARE_V2)`，再按 `GetDeviceCaps(LOGPIXELSY)/96` 算出缩放比，所有像素常量都过一遍 `S(v)` 宏，布局才算稳。
- **字体统一加粗**：一开始按钮粗、标签细，看着像两套 UI；后来把标签、输入框、日志、列表的字体全改成 `FW_BOLD`，RichEdit 里也统一 `CFE_BOLD`。
- **登录方式做成三个胶囊按钮**（password / cookie / public），比下拉框直观，切换时标签和提示文字跟着变。
- **右下角的「♥ 赞助」**：一开始想做成弹窗或菜单项，太吵；最后就是窗口右下角一行暗色小字，自绘（`BS_OWNERDRAW` + `WM_DRAWITEM`），按下时才变绿。点它只做一件事——把赞助页链接写进剪贴板，不启动浏览器。刻意不打开网页，是因为突然弹出浏览器很打断人，愿意支持的人自己粘贴就行。
- **试过又撤掉的功能**：给中括号里的难度和分数按洛谷官方色上色。做出来之后觉得「颜色乱跑」，同一屏里七八种颜色抢视线，最后回档成统一白色，只保留分组标题里的难度名。这个决定留在了代码里：`DiffColor()` 函数还在，但列表渲染统一用 `C_EDITFG`。

## 五、关键实现

### 5.1 三种登录

- `password`：GET 登录页拿 `__csrf`，再 POST `/auth/login`；成功率取决于洛谷风控，失败时会提示改用另外两种。
- `cookie`：把浏览器里的 `_uid` / `_client_id` / `__csrf` 拼成 Cookie 头直接请求，绕过登录流程。
- `public`：只填用户名或 UID，走公开接口查通过记录，不涉及任何凭据。

### 5.2 拉取已通过题目

先用 `/user/_contentOnly` 拿到 uid 和通过数，再按页请求 `/user/{uid}/problems?_contentOnly=1&page=N`，从返回的 JSON 里抽 `pid` / `title` / `difficulty`。题目列表要分页，几百题就是十几次请求，所以放在工作线程里跑，主界面只负责刷日志。

### 5.3 计分

```
Rating = （分数最高的 50 道题之和） ÷ 50
```

不足 50 题也除以 50 —— 这条是用户明确要求的，否则只做过几道水题的新号会显得比老号还强。

单题分数按洛谷难度标签定基准（入门 400 … 黑 3200），同档内再用通过率的 logit z 分数拉开 ±180；紫档里通过率最低的 25% 抬进 3200~4000；提交量小的题按 `√提交量/40` 的置信度向基准收缩。完整表格见 `docs/评分算法与分数表说明.md`。

### 5.4 列表与挑题

RichEdit 控件按行插入文本，用 `CHARFORMAT2` 控制加粗和颜色；双击列表用 `WM_NOTIFY` 取光标所在行，解析出题号后 `ShellExecute` 打开浏览器。挑题弹窗按当前 Rating 找难度略高、且还没做过的题，提供「是 / 否」直接打开或复制链接。

### 5.5 待做清单：为什么最后自己画列表

待做清单第一版是直接用 RichEdit 的：文本里插 `\u0001` 之类的占位符，再用 `CHARFORMAT2` 的 `CFE_STRIKEOUT` 给做完的题加删除线。用起来有三个毛病：

1. **删除线是断的**：RichEdit 只在有字形的字符上画线，遇到空格、或者字体回退到别的字形时线就断一节；
2. **做完的行整体变灰**，看上去比未完成的行「细」，字重不统一；
3. **点哪儿都在选字**，没法做成「点行首的小方框勾掉」。

所以把列表换成了自绘的子窗口（窗口类 `L"LuoguTodoList"`），一次解决三件事：

- **方框自己画**：未完成是空框 `C_EDITBG` 底 + `C_SUB` 边框，完成是 `C_GREEN` 底 + `C_BG` 色的勾；命中测试只看这个矩形，点上就 `TodoToggle`。
- **删除线自己画一根**：从文字起点画到题目名的实测宽度处，粗细 `S(1)+1`、颜色 `RGB(150,150,172)`，一路铺满不断线；字仍然是 `C_EDITFG`、仍然是同一个粗体，只是多了根线。
- **一题一行不折行**：先用 `GetTextExtentPoint32W` 实测每段文字的像素宽，题目名超出预算就用 `TodoFit` 截断加省略号，而不是让控件自己折行。

行数据放在 `g_todoRows` 里，`kind` 0 是小标题（「—— 还没做 ——」）、1 是题目、2 是空行；绘制和命中都按这个数组走，所以「未完成 / 已完成」分组、`↑` `↓` 换行、滚轮滚动都只是改下标。

### 5.6 算法掌握：在内存里算「最好 5 题」

需求是「这个算法的题，我做出来的分数对不对得上我的 Rating」。第一版取的是该算法所有题的平均分，结果被简单题拖得很惨——模拟那栏 38 道题、均分 601，看着像不会写模拟，其实只是刷了很多入门题。改成**取最好的 5 道**之后，同一批数据变成 1223（+237），才符合实际手感。

实现很轻：

- `struct AlgoStat` 里存 `n`、`sum`、`best`（降序最多 5 个），每题用 `std::greater<int>` 维护这个 5 元素小数组；
- 循环结束后 `k = best.size()`，`bestAvg = (sum(best) + k/2) / k`（加 `k/2` 是做四舍五入）；
- `delta = bestAvg − Rating`：`≥ +60` 记优势，`≤ −60` 记薄弱，中间算均衡；`n < 4` 标「样本少」，不参与结论。

题目到算法的映射来自 `data\algorithm_index.jsonl`（`{"pid": "...", "tags": [...]}` 一行一道），启动时读进内存，之后所有统计都在内存里做，不联网。推荐题则是从同一份索引里筛出该专题、参考分落在 Rating 上下区间的题，再按分数升序排。每一行最左边画一个「复制 / 看做过」小按钮（`AlgoHitButton` 与 `AlgoListPaint` 用同一套行高和偏移算矩形，所以点得到的地方就是画出来的地方），点了不是去拉浏览器，而是把题面网址写进剪贴板——低完整性进程用 `ShellExecute` 启动 Edge 经常静默失败，复制网址反而是最稳的一条路，这个教训是从「推分推荐」的弹窗那里沿用过来的。

## 六、踩过的坑

**工具链**

- `ld` 静默退出（返回码 5）、`ld --version` 直接 127：bin 目录缺 `libintl-8.dll`（binutils 依赖它），从 gettext-runtime 包里抠出来补上。
- `cannot find -lpthread`：缺 winpthreads 的静态库，且 `winpthreads-stub` 里的 `libpthread.a` 只是 8 字节空壳，必须用完整的 `libwinpthread` 包。
- 编译必须在命令前设 `TMPDIR` / `TMP` / `TEMP`，否则 `ld` 建不了临时文件。
- exe 正在运行时会报 `cannot open output file LuoguScorer.exe: Permission denied`，先 `taskkill`。
- 资源要先用 `windres` 编成 `.res` 再和源码一起链接（`windres -I. luogu_scorer.rc -O coff -o tmp/app.res`），直接 `g++` 编译 `.rc` 会找不到 `windres` 的临时文件。

**自绘控件**

- 自绘窗口类注册时只写 `CS_HREDRAW | CS_VREDRAW`，忘了 `CS_DBLCLKS`，系统就**永远不发** `WM_LBUTTONDBLCLK`——真实鼠标双击彻底失效，而用 `SendMessage` 手工发这条消息却「测试通过」，自测骗过了自己。教训：自测要发的是**系统真的会发的那条消息序列**（或干脆加个按钮，不赌双击）；`GetClassLongPtrW(hWnd, GCL_STYLE) & CS_DBLCLKS` 一行就能验证类样式到底有没有生效。
- 自绘列表收不到滚轮：`WM_MOUSEWHEEL` 只发给有焦点的窗口，得在主窗口里判断光标是否落在列表矩形内，再转发过去。
- 广告牌动画的定时器必须 `SetTimer(g_hWnd, ...)` 挂在**主窗口**上；挂在自绘子窗口上，`WM_TIMER` 就进子窗口过程，主循环里的推帧逻辑永远不执行。并且只在「真的有人放不下」时才启动定时器，静止画面一帧都不多画，否则一个 35ms 的定时器会白白吃掉 CPU。

**发布**

- 一开始以为「加了图标 + 版本信息就不会被拦」，实测照样弹 SmartScreen：它只认签名和下载量。后来把「怎么解除锁定」和「代码签名路线」写进了 README 和教程 9.10，比在代码里折腾有效得多。

**界面**

- 截图老是拍到空白列表：窗口刚重排时 `PrintWindow` 抓到的是旧画面，要等 2 秒以上再截。
- 加粗之后启动页状态行硬折行，只好拆成两行：第一行账号 / UID / Rating，第二行计分公式。
- 待做清单用 RichEdit 加删除线时，线在空格和字体回退处会断开，而且做完的行一灰就显得字细；最后整块换成自绘列表，线和方框都自己画才彻底。
- 自绘子窗口收不到滚轮（滚轮发给焦点窗口），要在主窗口的 `WM_MOUSEWHEEL` 里判断光标是否落在列表内，再 `SendMessage` 转发过去。
- 中文题名按「半角字符数」估宽度是不可靠的，同一行里英文和汉字的宽度不一样，估出来的预算会让尾巴折到第二行；改成用 `GetTextExtentPoint32W` 实测宽度再截断。

**数据**

- 「难度虚高」导致掉档：有的题分数算得低，却被归到「普及」组。改成**档位以洛谷难度标签为准**，只有分数 ≥ 3200 才升进黑档。
- 分数表第一版生成时把分位方向写反了（通过率 73% 的黑题算出 3857 分），改 `p = i/(n−1)` 后正常。
- 最惨的一次失误：重跑生成脚本时用 `rm -f data/difficulty_scores.backup-*.json` 清临时文件，把**原始分数表的备份一起删了**。旧版逐题分数不可恢复，只剩下某个账号 318 题的旧快照能对照。教训：备份目录和临时目录要分开。

## 七、分数表的审核与重做

分数表最初是「按难度基准 + 一点通过率微调」生成的，用起来发现问题成堆，于是对它做了一次完整审计（45802 题，全部能在原始统计里对上）：

- 同档区分度太小：入门~省选有 90% 以上的题离基准不到 50 分；
- 黑档系统性算错：1967 道黑题里有 1051 道分数低于 3200，最低只有 376；
- 紫/黑边界跳变：紫档一堆题卡在 2800~~2999，另一堆直接 3000~~3500，中间没有过渡；
- 「未评定」的题被随手赋了 323~3500 分，没有依据。

后来按「同档 logit z 分数 ±180 + 紫档后 25% 抬到 3200+ + 黑档 3200~4000 + 置信度收缩」重算了一遍，相邻档不再交叉，同档内分数与通过率的 Spearman 相关稳定在 −0.9 左右。审计过程和前后对比都在 `docs/评分算法与分数表说明.md`。

## 八、打包与发布

- 目录按「源码 / 可执行 / 数据 / 文档 / 脚本」分好，exe 放根目录，因为它只认自己旁边的 `data\`。
- `.gitignore` 排除 `accounts.json`、`session.json`、`accounts/`、`others/` 等个人数据，成绩不会被推到公开仓库。
- 生成脚本里的绝对路径改成按脚本位置定位，别人 clone 下来直接能跑。
- GitHub Actions 里用 MSYS2 的 MinGW-w64 编译一遍，产物作为 artifact 上传。
- exe 里嵌了图标、`VERSIONINFO` 和 manifest（`asInvoker`、Per-Monitor V2 DPI、`longPathAware`），链接时开 `--nxcompat --dynamicbase --high-entropy-va`，最后 `strip` 掉符号（1.0 MB → 约 550 KB）。这些都只是让二进制显得更正常，真正消掉 SmartScreen 弹窗只能靠代码签名。
- MinGW 的 `endfile` spec 会自动再塞一份 `default-manifest.o`，和 `.rc` 里那份撞车（`.rsrc merge failure: multiple non-default manifests`，而 `-Wl,--no-manifest` 是 ld 不认识的选项）。最终用一份只改 `*endfile` 的 `nomanifest.spec` 解决，并加断言：`strings LuoguScorer.exe | grep -c "assembly xmlns"` 必须等于 1。
- 发布前把整个目录拷到别处跑一次，确认读的是包内的分数表（Rating 与开发目录一致）。

## 九、使用教程

### 9.1 安装与启动

1. 在仓库页面点 `Code → Download ZIP`，解压；或者 `git clone`。
2. 双击根目录的 `LuoguScorer.exe`。**不要**把 exe 单独拷走——它只认自己旁边的 `data\` 目录。
3. 不需要手动建 `data\` 目录（缺了会自动建）；`accounts.json` 只在「个人账号」里注册后才会生成。
4. 系统要求：Windows 10 / 11 x64。程序没有代码签名，SmartScreen 或杀软可能拦一下，点「更多信息 → 仍要运行」，或者按 [BUILD.md](../BUILD.md) 自己编译一个。

启动页按行排按钮：**开始**（去查洛谷）；第二行 **每日一题** / **推分推荐**；第三行 **我的成绩** / **待做清单** / **算法掌握** / **个人账号**。如果之前登录过，底部会显示当前账号、UID、Rating 和计分公式，最下面一行是「本工具完全免费，由鸣破音弦制作」。

### 9.2 选择登录方式

点「开始」进登录页，顶部三个胶囊按钮切换：

| 方式         | 要填什么                              | 什么时候用                         |
| ---------- | --------------------------------- | ----------------------------- |
| `password` | 洛谷账号 + 密码（`_client_id` 可留空）       | 最省事，但容易被洛谷的人机验证拦；失败时会提示换下面的方式 |
| `cookie`   | `_uid`、`_client_id`、`__csrf`（可留空） | 密码登录走不通时最稳                    |
| `public`   | 用户名或 UID，密码留空                     | 只查公开的通过记录，不登录、不碰任何凭据，最安全      |

Cookie 的取法：浏览器登录洛谷，按 F12 → Application / 存储 → Cookies → `www.luogu.com.cn`，把 `_uid`、`_client_id`、`__csrf` 三个值复制过来即可。这些值只在当次请求里用，不写盘。

填好后点「登录并获取已通过题目」，下面的日志会一行行打印进度（定位 UID、拿到了多少题、每题的链接）。查完会自动进入成绩页。

### 9.3 看懂成绩页

成绩页分三块：

**顶部大字**：昵称、洛谷 UID、本机账号名，以及 Rating。下面一行是计分依据：

```
Rating = 最好的 50 道题总分 ÷ 50
```

所以题数不满 50 时 Rating 会明显偏低——这是有意的，避免刚做几道水题就显得很强。「分布」那一行是各难度档的题数。

**中间按钮**：

- **B50 最佳 50 题**：只看贡献 Rating 的那 50 道；
- **总览全部**：列出所有已通过的题；
- **区分方式**：在「按难度分组 / 按分数 / 按题号」之间循环切换；
- **重新查询**：重新从洛谷拉一次数据（做了新题之后点这个）；
- **返回**：回启动页。

**列表**：每行是 `[难度 分数] 题号 题目名`，分组视图下每组开头有「—— 难度 · 共 N 题 · 平均 X 分 ——」。**双击题号**用默认浏览器打开这道题；打不开就手动复制题号。

### 9.4 每日一题 / 推分推荐

两个按钮都在启动页，区别是难度：

- **每日一题**：在 Rating 上下 200 分内（不够再放宽到 400）挑一道你还没做过的题，同一天再点会先给同一道，可以选「换一道」；
- **推分推荐**：挑一道比现在水平高约 100 分的题，用来推分。

弹窗里会写题号、题目名、难度、分数，以及「比你的 Rating 高多少」。点「是」默认用浏览器打开，系统拦了就打不开的话会改成把网址复制到剪贴板，你在地址栏 Ctrl+V 即可。

### 9.5 待做清单

启动页点「待做清单」，按账号存在 `data\accounts\<账号>\todo.json`。

- **自动记一笔**：点「每日一题」或「推分推荐」抽到的题会直接进清单，来源栏写「每日一题」/「推分推荐」。
- **自己导入**：题号粘到输入框，多个用空格或逗号隔开（`P1001 P1002 B2001`），点「添加」。认不出的会提示「没认出来」。
- **做完自动划掉**：点「同步成绩」拉到新的通过记录后，清单里已经通过的题会被划掉，但**不从清单里删除**——字还在、颜色和字重都不变，只多一道横线。
- **分开看**：默认分「—— 还没做 ——」和「—— 已经做完（划掉了）——」两组；点「只显示未完成」可以把做完的藏起来。
- **手动改**：点每行前面的小方框就是勾掉 / 恢复；先点一行选中，再点「勾掉 / 恢复」「删除选中」也行。`↑` `↓` 换行、空格勾掉、滚轮滚列表。
- **题名会补全**：添加时还不知道题名的，等下次拉通过记录时补上；一直没做过就显示「（题名未知）」。

### 9.6 算法掌握

点启动页的「算法掌握」，看的是：**这个算法的题，我做出来的分数对不对得上我的 Rating。**

- **判定标准**：取你在该算法上**做得最好的 5 道题**（不足 5 道就全取）算均分，和 Rating 比：高出 60 分算「优势」（绿），低 60 分算「薄弱」（红），中间算「均衡」；只做过不到 4 道题标「样本少」，不给结论。
- **两个视图**：「全部算法」按基础 / 进阶 / 高级分组列 45 个专题；「只看优势」「只看薄弱」过滤。
- **看推荐题**：选中一个专题再点「看推荐题」，会从索引里挑该专题、参考分在你水平上下的题，按分数从简单到难排，点「回到算法列表」继续看别的。
- **行首「看做过」按钮 = 我做过哪些题**：每个专题那一行最左边有个小按钮，点它列出你在这个专题上通过的每一道题，按分数从高到低排，前 5 道前面标一颗 ★——就是判定「优势 / 薄弱」时算均分的那几道，看得见结论是怎么来的。
- **行首「复制」按钮 = 复制题面网址**：推荐题和我做过的题，每行最左边也各有一个「复制」小按钮，点它把 `https://www.luogu.com.cn/problem/题号` 复制到剪贴板，不依赖浏览器能不能被拉起来。
- 之所以做成「按钮」而不是「双击行」：自绘列表窗口类注册时如果没写 `CS_DBLCLKS`，系统根本不会发 `WM_LBUTTONDBLCLK`，真实鼠标双击永远是失效的（`SendMessage` 伪造这条消息却会「通过」，很容易自测骗过自己）。按钮比双击显眼，也不用赌系统消息。
- **长题名像广告牌那样滚**：题名放不下时不再截成「…」，而是在题名列里一路往左滚，滚到头从右边接着出现，一直循环——每帧只把整段文字往左挪 `g_mqPos` 像素，偏移量取 `g_mqPos % (文字宽 + 间隙)`，然后把同一段文字画两遍（`x0` 和 `x0 + total`），用 `SaveDC` + `IntersectClipRect` 裁到列内，于是第二遍正好从右边补进来，接缝处不会空。短名字根本不动，只有真放不下的才滚。待做清单里的长题名同样处理，那根删除线也跟着每一遍文字一起移。
- 依赖 `data\algorithm_index.jsonl`（15564 道 P/B 题的算法标签索引）。删了会弹提示，重新拷一份回来，或跑 `python tools\build_algo_index.py` 重生成。

### 9.7 个人账号（成绩归档）

想留下历史成绩，就在启动页点「个人账号」：

1. 账号名随便起（只在本机用），密码至少 4 位，绑定你的洛谷 UID 或用户名；
2. 点「注册」，成功后点「登录」；
3. 之后每次查询，成绩都会归档到 `data\accounts\<账号名>\` 里，按时间戳留快照。

这里的密码是**本机账号的密码**，只保存 `salt + SHA-256`，和洛谷密码无关；忘了只能删掉 `data\accounts.json` 重新注册。查别人的账号不会写进你的档案，会单独存到 `data\others\<uid>\`。

### 9.8 数据、备份与手改分数

`data\` 里值得备份的只有三样：`accounts.json`（本机账号）、`accounts\`（成绩快照）、`session.json`（当前登录的是谁）。`config.json` 和 `difficulty_scores.json` 可以随时从仓库重新拿。

想给某道题指定分数（比如觉得某题难度标偏了），在 `data\problem_rating.json` 里写：

```
{"P1012": 900, "P1090": 1000}
```

这个文件优先于自动分数表。想整表重算就改 `data\problems*.jsonl` 后跑 `tools/gen_scores.py`（会先备份当前表，再重写 `difficulty_scores.json`）。

### 9.9 常见问题

| 现象              | 原因                        | 处理                                         |
| --------------- | ------------------------- | ------------------------------------------ |
| 双击没反应 / 一闪而过    | exe 旁边没有 `data\` 目录，或被杀软拦 | 整个文件夹一起用，别只拷 exe                           |
| 提示「Windows 已保护你的电脑」 | 没有代码签名 + 文件带「网络下载」标记 | 右键 exe → 属性 → 勾「解除锁定」；详见 9.10                |
| 登录失败，提示人机验证     | 洛谷风控拦了密码登录                | 改用 `cookie` 或 `public`                     |
| 日志里 HTTP 404    | 洛谷接口路径变了                  | 换 `public` 试试；仍不行就是接口改了，需要更新程序             |
| Rating 是 0 或异常低 | 没查到通过记录，或分数表缺失            | 确认 `data\difficulty_scores.json` 在；点「重新查询」 |
| 题号双击没反应         | 系统没关联默认浏览器                | 手动复制题号到浏览器                                 |
| 字体偏小 / 偏大       | 非整数缩放（125%、175%）          | 已做 Per-Monitor DPI 感知，仍有问题请带缩放比例反馈         |
| 换电脑后账号没了        | `data\accounts.json` 没一起拷 | 把 `data\` 整个目录拷过去                          |

### 9.10 被 Windows 拦住了怎么办

从 GitHub 下载 ZIP、解压、双击 exe，Windows 可能弹「Windows 已保护你的电脑」。原因是 ZIP 里的每个文件都带着一条「来自网络」的标记（Mark-of-the-Web），而这个 exe 没有代码签名，SmartScreen 不认识它。

三种解法：

1. 右键 exe → **属性** → 常规页最下面勾「**解除锁定**」→ 确定，再双击。
2. 在解压目录里打开 PowerShell，一次性清掉所有文件的标记：

   ```powershell
   Get-ChildItem -Recurse -File | Unblock-File
   ```

   仓库里还带了个脚本，效果相同：`powershell -ExecutionPolicy Bypass -File tools\unblock.ps1`。
3. 弹窗里点「更多信息 → 仍要运行」。

如果是杀毒软件报毒（而不是 SmartScreen），那属于启发式误报，可以加入信任目录，或者干脆自己编译——见 [BUILD.md](../BUILD.md)。

**代码层面为什么解决不了**：SmartScreen 判断的是「受信任 CA 的签名 + 下载量累积出来的声誉」，和程序内部写了什么无关。自签名证书也不管用。真想让弹窗消失，只能申请代码签名（开源项目可申请 [SignPath Foundation](https://signpath.org/) 的免费签名，或使用 Azure Trusted Signing），而且签名后还要靠下载量慢慢养声誉。

程序这边已经尽量「看起来正常」了：嵌了图标、`VERSIONINFO`（属性页能看到「洛谷计分器 1.1.0.0」）、manifest（`asInvoker`，不触发 UAC），链接时开了 DEP/ASLR 并 `strip` 掉符号，二进制里也没有加壳、自解压或下载器行为。这些能降低误报概率，但绕不过 SmartScreen 的声誉检查。
