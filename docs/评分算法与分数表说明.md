## 三、发现的问题

### 1. 同一档内几乎没有区分度（最主要的问题）

d=1~6 里，|分数−基准| ≤ 50 的题占 90.7%~94.8%，同档最高与最低只差 150 分左右。
而真实差异可以拉满一整档：例如「通过率 80%」和「通过率 5%」的同档题，水平差距远不止 150 分。

后果：B50 里同档题基本等价，你花 10 分钟做出的普及题和一下午才过的普及题算一样的分。

### 2. 黑档（d=8）系统性算错

- 1967 道 d=8 的题里，**1051 道分数低于 3200**，最低到 376。
- 其中 **406 道通过率 ≥ 40%**，这些明显是把「紫/黑按通过率拆分」的公式又用了一次，把黑题按紫档的基准重算了一遍（还带了负向修正）。

典型样本（通过率其实很高，却被算成入门/普及分）：

| --- | --- | --- | --- |

| P5326 | 381 | 1370 | 69.9% |
| P8990 | 381 | 1238 | 70.0% |
| P1971 | 400 | — | — |

### 3. 紫/黑边界是跳变

d=7 中 2714 道停在 2800~2999，910 道直接跳到 3000~3500，中间几乎没有过渡。
边界附近的题（通过率 4%~6%）分数一夜之间差 200 分，谁碰上谁吃亏。

### 4. 未评定（d=0）没有依据

354 道题被赋了 323~3500 的分，但洛谷本身没给难度标签。这些分只能算猜测，建议统一给 800（普及- 基准）或按通过率单独估计。

### 5. 远程题库 difficulty 语义不同

AT 里 639 道 difficulty=8 的题，通过率 70%~85% 的一大片（AT_agc035_f 84.5% → 364 分）。说明那份数据的 8 更接近「无评级」，不是「黑档」。这批题目前分数不可信（只会影响做过这些题的人）。

## 五、建议的算法

保持你现在的分档基准不变，只改分数的生成方式：

    rate = totalAccepted / totalSubmit

    d = 1..6：
        z = 同档内 logit(rate) 的 z 分数，clamp 到 [-1, 1]
        score = base[d] + round(180 * (−z))          # 同档内最多拉开 360 分

    d = 7（紫/黑拆分）：
        p = 同档内 rate 的分位（0=最难, 1=最易）
        p < 0.25 → score = 3200 + round(800 * (0.25 − p) / 0.25)   # 3200~4000
        否则     → score = base[7] + round(180 * (−z))，clamp ≤ 3199

    d = 8（黑档）：
        score = 3200 + round(800 * (1 − p))，任何情况下不少于 3200

    d = 0（未评定）：
        score = 800 + round(180 * (−z))（同 d=2 的处理），或直接给 800

    置信度收缩（提交量少的不敢给极端分）：
        c = min(1, sqrt(totalSubmit) / 40)
        score = base[d] + round((score − base[d]) * c)

这套做法的效果：
- 同档内分数不再是「基准 ± 50」，而是 ±180，能体现「这题其实比同档平均难」；
- 黑档永远 ≥ 3200，不会再出现「黑题 377 分」；
- 紫/黑边界从跳变变成 3200 起的连续区间；
- 提交量 20 次以下的题自动往基准靠，不会被 1/2 的通过率骗到 4000。
